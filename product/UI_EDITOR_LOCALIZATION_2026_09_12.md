# Editor interface localization — released PR132

This released implementation continues from PR131 (`18fd44a91432fa6940619c7267457d840bcf1f22`) and canonical main `32145aa7f427dca306eeb0758b8e362c743be753`, integrated through a normal merge. It adds 148 `editorScreen` messages in English, Polish, Swedish and Danish, with matching French authoring copy. Each current dictionary and staged French contain 2,850 effective keys; French spans13 batches and remains outside the runtime and picker. This is dictionary and editor implementation work, not a delivered French interface or fluent-user acceptance.

The editor and creation dialog now translate tabs, metadata/structure fields, content types, save/export controls, source and author panels, image controls/statuses, link resolution, preview controls, generation/retry outcomes and draft/live publication messages. Existing shared keys are reused where they preserve the same meaning. Complete sentences allow each language to order placeholders correctly and avoid English plural fragments. Source statuses remain validation-owned; supplied source claims, author names, credentials, URLs and content retain their original values. Typed source categories are translated only for display.

Ten date displays use the selected interface language. Shared date helpers accept an optional locale while preserving UTC audit dates, browser-local schedule dates, fixed24-hour clocks, invalid-date dashes and original English output for existing callers. Local picker values still round-trip through ISO serialization without shifting their displayed wall clock. Timestamp values, schedule windows, calendar interpretation and actual database dates are unchanged.

The copy corrects three misleading promises: deleting a draft no longer claims its best-effort schedule cancellation always succeeded; the preview no longer promises an exact live appearance; and the replacement picker no longer calls every owner-approved page independently verified. Link approval confirms that a path may now be included as a link, not that all publication requirements have passed. Source resolution, advisory author recommendations, private upload/public approval distinctions, generated versus accepted image status, draft sending versus live publication, CMS-dependent structured-data retention and the absence of a guaranteed rich result remain explicit.

Draft/content values, operation identifiers, default content-type selection, generation and blank-draft behavior, export/save handlers, per-link decisions, canonical article assembly, publication approvals, credential boundaries, metering and schedules remain unchanged. The AI action name type is restricted to its existing metadata/CTA/FAQ callers so notification labels can be translated. The creation dialog's unused options export was removed; the existing onboarding default-type helper remains exported. Persisted fallback image concepts remain unchanged instead of being rewritten in the interface language.
