# Shared scheduler preparation capacity

R06 requires visible quota shortages and interrupted-work explanations. The monthly scheduler already caps generation from the server-owned usage counter, but the notification sweep did not warn when remaining capacity could not cover the enabled schedule.

This packet projects the same next-month horizon, configured weekdays/time zone, booked slots and saved/legacy held-draft accounting as the existing scheduler. It sums missing preparation across all active projects in the owner's workspace before comparing against the shared account counter. It does not allocate a separate copy of the account allowance to every project. Disabled schedules and fully covered projects produce no capacity event.

The server reads only plan/status/period-end, the owner role, and current UTC-month contentGeneration usage, with account filters and a two-row bound to detect unexpected duplicates. Missing rows have their existing free/no-use meaning. Errors, malformed values and duplicates yield unavailable evidence, not a zero allowance. Existing entitlement/cap semantics are reused. These separate reads are a planning snapshot, not a transaction or reservation; execution still performs atomic claims. Current counters measure preparation attempts, not confirmed delivered-result allowances or monetary budgets. The UI states the current usage period and next planning period explicitly; it does not promise that attempts produce completed articles.

Two incident kinds distinguish low capacity from unavailable verification. Their keys are stable per project, kind and usage/planning period; changed counts update the current incident. A fresh scan resolves shortage after additional capacity, fewer slots, saved work or pause. Metering failures keep the other operational events available. No quotas, funded budgets, model calls, subscriptions, automatic retries, approvals or publication permissions are changed. The existing opt-in outbox can render the new kinds in PL/EN/SV/DA, but this packet neither enables email nor sends anything.
