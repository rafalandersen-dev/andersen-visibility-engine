# External draft state and assessment safety

Source review found update_content_draft only rejected a published/sent marker, so an Approved non-live article could be changed while preserving its approval and old quality/assembly/readiness cache. Its response nevertheless always said Draft. Create retries could also relabel the response as Draft after the actual record had progressed to Approved/Exported.

The write boundary now requires actual Draft status, an existing project in the caller's workspace and no known external publication binding, attempt status or pending/uncertain schedule mirror. Published, publishing, failed/uncertain, approved/reviewed/exported and orphaned records are refused without mutation. An explicitly cancelled schedule remains cancelled. The existing MCP content scope, write flag and rate hook remain authoritative; no approval, scheduling or publishing scope is added.

For valid Draft edits, a substantive field change marks an existing quality score stale and removes derived assembled/checklist/readiness results. Notes-only and identical content do not invalidate an unchanged assessment. Authored images, hooks and persistent section identities survive; the existing read-time section resolver still handles body changes conservatively. This helper is also prepared for later image attachment, but no image upload tool is exposed by this packet. Create retries return the existing record's actual status rather than claiming a new Draft.

Validation combined with main #83: 1,577 tests/120 files, TypeScript/build pass, new helper/tests standard lint and diff checks pass. Twenty-four added cases cover publication/approval/schedule state rejection, cancelled Draft preservation, stale assessment removal, notes-only edits, immutable-field guard, orphaned projects, real MCP dispatch and replay status. No live customer content was changed. This is a source/workspace boundary, not independent CMS destination reconciliation or a replacement for authoritative queue/approval concurrency acceptance.
