# Bounded connected-assistant topic batches

`create_opportunities_batch` accepts 1–25 authored topics under existing milo.projects.write and the existing write gate/rate hook. Strict validation rejects unknown fields, publication status and malformed inputs before mutation. Topics become canonical captured opportunities without AI generation, publication or queue insertion. The source can be generic mcp or competitor; existing Claude-origin records retain their labels.

A pure revision-guarded mutation writes the entire batch and a project-scoped replay receipt together. IDs, timestamp and normalized request fingerprint are prepared before the callback can repeat. A retry returns the existing IDs only when its receipt and complete topic set still match. Changed payloads or removed topics require review; receipts prevent resurrection even if every topic was deleted. Later topic lifecycle changes are preserved on replay; the response says stored, not that an existing published topic is newly captured. Receipt/topic bounds fail without partial insertion or silent receipt pruning. Unknown or other-account projects remain indistinguishable as not found.

Bounds: 25 items per call, 1,000 opportunities per workspace and 1,000 retained batch receipts per project. No automatic ledger pruning or privileged recovery override. Receipts are stored with the existing project entity, so no new database migration is needed. Failed revision retries must use the same requestId. Audit logs contain IDs, field names and counts, never topic titles or rationale.
