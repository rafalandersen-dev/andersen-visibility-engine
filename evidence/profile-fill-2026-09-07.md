# Direct fill-empty profile ownership

The approved August authoring scope distinguishes direct filling of blank profile fields from owner-reviewed changes to existing values. Project readiness (#76) and deep Brand Intelligence proposals (#79) were present, but every profile write still required the proposal path.

`fill_project_profile` now fills only absent/null/whitespace-only text or empty arrays in an existing project. A non-empty list is preserved as a whole. Only the existing whitelisted profile fields and validated Brand Intelligence leaves are accepted; services, opportunities, identity, publishing, setup completion, billing and connector configuration are excluded. Input is bounded to16KiB of UTF-8 payload plus per-field limits. URLs are stored, never fetched. Empty proposed values and identical existing values are no-ops.

Owner-set values are retained and returned as field names under `requiresProposal`, for the existing `project_setup_proposal` workflow. No approval or proposal is fabricated. Scope remains `milo.projects.write`, with the existing write gate/rate hook and workspace revision mutation. Ownership is re-evaluated against the latest snapshot on every revision retry. Audits record validated names only, never research/profile values.

A project-scoped durable receipt binds each stable requestId to a canonical payload hash. Identical replays report `previously_processed`, explicitly describing the original outcome, and never refill a field the owner subsequently cleared. Changed payloads are refused. Receipts are validated against known field names before response/audit use and bounded to200 per project; exhausted history directs the caller to owner-reviewed proposals. No destructive pruning or per-retry receipt IDs are introduced. This is bounded to the stored project's lifetime, not a guarantee after arbitrary manual database restoration or project deletion/recreation.
