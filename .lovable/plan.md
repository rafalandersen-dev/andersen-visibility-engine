# Milo Content Factory — architecture audit and implementation plan

## Recommendation and evidence boundary

Build a default-off, isolated **Synergy Massage** module: **evidence → idea → script/caption/carousel → exact-package approval → calendar date → manual publishing export**. Reuse Milo’s contracts, not its website publishing lifecycle. Start Instagram-first with manual export; no external publishing integration is necessary for MVP.

Read-only audit, 25 November 2026, repository `c5cc7c339d1a2b45bbd6574e2f951527729eab37`. Inspected source, migrations, test files, existing scan results and bounded database SELECTs. Only this plan is written. No application/dependency changes, database writes, settings changes, provider calls, mail, worker execution or deployment. Tests/builds were not run. Everything below is proposed, not production acceptance or expanded launch authorization.

## Smallest complete MVP

1. **Evidence-linked ideas:** read shared project knowledge without changing it. Import supplied excerpts/documents/official exports manually, with URL/title, source language, observation/import dates, locator, fingerprint, permission-to-use and genuine supplied metric/window if any. A URL alone is not evidence; no automatic scraping/fetching. Separate creative inspiration from factual support. Missing, stale or disputed evidence remains flagged; never invent trend/engagement figures, testimonials or outcomes.
2. **Scripts/captions:** manual editing always works. Only with separately approved budget, one bounded request proposes up to three ideas; a second request for the selected idea produces script scenes, caption/CTA and up to five slides together. Validate evidence IDs against included context and require human claim-support review; valid IDs alone do not certify truth.
3. **Editable carousel:** one 1080×1350 template, 1–5 slides; editable text/order, approved colors/font/logo, rights-cleared supplied photos and alt text. Reuse raster validation and installed JSZip; browser Canvas renderer, no paid image generation. Save editable JSON and freeze PNG bytes for review/export. Missing assets/branding or overflow blocks approval, not editing.
4. **Approval/calendar:** owner-only pilot first, matching existing owner approval. Queue retains rejection/history; approval covers exact slides/media bytes, brand/source revisions, caption/script, language, destination and UTM manifest. Edits invalidate applicability. Dates are planning only, with explicit timezone/UTC instant and DST validation. Delegated review follows existing viewer/editor/reviewer policy only when already authorized; no new invitations required for MVP.
5. **Manual publishing package:** ZIP of approved PNGs, caption/script, alt text, editable JSON and evidence/UTM manifest. Unapproved source downloads remain labeled as drafts. Example: `utm_source=instagram`, `utm_medium=organic_social`, stable campaign/item IDs, never personal data. Preserve valid query parameters; validate destinations and resolve Synergy’s relative booking CTA against its project origin. Record export separately from owner-reported post URL/time/channel; neither proves live publication or conversions.
6. **Tracking:** retain campaign/link identity and optionally import genuine platform/GA4 report files with source/window. Unknown metrics stay unknown. UTMs enable attribution but do not prove the destination captures it. No new tracking script, automatic social report, or relabeling existing GA4 figures in MVP.

## Technical design and isolation

- Add `src/features/content-factory/`: schemas, evidence/version/UTM/calendar helpers, context adapter, repository, authenticated `.functions.ts`, server helpers, browser renderer, views and focused tests. Thin `_authenticated/app.content-factory` routes for index/sources/editor/review/calendar; parent renders Outlet. Reuse AppShell, tokens/controls and i18n; only a gated nav entry and leaf metadata integration.
- Extract `projectBrief` into a shared helper with parity tests and unchanged old callers. Reuse `loadProjectKnowledgeContext` and bounded project/service reads. New manual sources remain in Factory storage: accepting social inspiration must not alter shared brand memory or weekly SEO inputs.
- Proposed additive tables: `content_factory_projects` (trusted flags/limits, module brand kit), `content_factory_sources`, `content_factory_items`, immutable `content_factory_versions`, append-only `content_factory_events` (reviews/attempts/exports/reported publications). Owner/project composite keys and project foreign keys; no new auth-schema references. Paginate 50/page and fail visibly at explicit limits. A dedicated private Factory bucket avoids article promotion/cleanup; reuse upload validation, not public lifecycle.
- Tenant key is **owning account UUID + project ID**, never name/host/active-project UI state. Actor comes from existing auth middleware. Check project, current membership, feature gate and role on every operation; transactionally recheck authority/source/media versions on approval/export. No cross-project cache or delegate workspace fallback. RLS and explicit least-privilege GRANTs on every new table; no direct client grants for flags, limits or approvals. Ordinary reads remain caller-scoped; privileged operations authorize before admin access. Private URLs expire; no credentials in packages/logs.
- Trusted default-off `contentFactory` flag pinned to the existing Synergy owner/project tuple, never rebound to the current visitor. Independent default-off AI/local-media/Meta/analytics/autopilot capabilities; server gates, not just hidden navigation. Disabling stops new Factory actions without touching website publishing.
- **No writes/calls to:** website content/statuses, `scheduled_publishes`, schedule mirrors, publication approvals, weekly readiness/executor state, existing team-policy setters, publishing/preparation workers or GA4 daily jobs. No changes to their gates, schedules or budgets. Factory approval/date/export never invokes a connector.

## Languages, privacy and costs

- Reuse all 24 EU content codes independently of UI/source language. MVP UI EN/PL/SV/DA; Swedish first, other pilot languages on request. Each translation has separate review; remaining EU languages need fluent acceptance before quality claims. Test diacritics, Greek/Cyrillic, wrapping and Stockholm DST.
- Sources are untrusted evidence, not instructions. No patient histories, identifiable treatment records or unconsented photos. Retention/deletion requires an explicit policy; no automatic deletion or new tracking without consent. Analytics consent does not authorize publishing/autopilot.
- **Factory AI defaults to USD0 until explicit budget approval.** Proposal: USD5/month reservation sublimit INSIDE the existing USD50 global ceiling. Current code reserves USD0.50/text attempt: at most ten attempts under that sublimit, not an invoice estimate. Free accounts still need a manual grant. Atomic module/account/global admission and stable attempt IDs; uncertainty retains reservations and prevents automatic regeneration.
- One attempt/action, no automatic retries/tools/benchmarks; ≤64 KiB prompt, ≤8,000 output tokens, existing 60-second bound, positive completion plus strict schema. No subscriptions, new credentials, paid data/images or provider fallback. Provider availability/deployed budget configuration were not verified; existing hosting/storage is not claimed free.

## Staged rollout and checks

1. **Scope review:** owner approves the proposal; Claude authors and Codex independently reviews under the working agreement/fallback. Confirm pilot owner, source rights, brand assets and samples. Check active writers first; record architecture rules in AGENTS.md during authorized implementation. This audit grants no spend/deployment permission.
2. **Manual vertical slice:** isolated test/local schema and full import→edit→approve→calendar→ZIP journey; AI off. Test tenant/project/role denial, forged direct calls, pagination, save/reload, stale evidence, invalidated reviews, missing assets, export bytes/UTMs and DST. Browser E2E in authorized pilot/test state; inspect ZIP contents and desktop/mobile rendering.
3. **Bounded AI pilot:** only after explicit budget. Narrow receipt allowlist integration; persist Factory output before successful delivery/settlement. Fake-provider tests for no-budget/no-dispatch, quotas, races, duplicates, timeout/uncertain persistence, incomplete JSON and unsupported evidence. Separately budget human review of Swedish accuracy/brand fit; no unlimited evaluation.
4. **Limited release:** separately authorized deployment and Synergy flag enablement; three approved packages for manual use. Independent release/deep-scan review, production access/export verification and unchanged website queue/gates evidence. Distinguish exports, reported posts and measured metrics. Rollback disables Factory capabilities and retains records.
5. **Later, separately approved:** local FFmpeg/Whisper on owner hardware, not bundled into the app server; bounded authenticated jobs, supplied media rights, local model/compute/storage limits. Then official Meta API publishing/analytics after current API/account/scopes review, token handling, idempotent receipts/reconciliation and genuine metric windows. Finally opt-in autopilot with explicit project/channel authorization, budget, revocation/kill switch and its own queue. Never infer it from calendar dates, one approval, analytics connection or website autopublish; no consumer automation or terms-violating scraping.

**Implementation validation packet:** new Factory tests plus targeted `bunx vitest run` on existing knowledge, generation-usage, AI-expense, team-review, calendar, language, image-storage, weekly-readiness/executor, publish-cron and GA4-daily tests. Migration authorization tests use the existing isolated harness. Typecheck and production build through required CI/platform checks. Report exact commands/pass counts/errors, paths and SHA, plus authorized persisted-flow/download evidence. No tests or live acceptance are claimed now.
