# Milo Content Factory — architecture audit and staged MVP plan

## Decision and audit boundary

Build an isolated, default-off module, piloted with **Synergy Massage**. Reuse Milo’s business context, evidence validation, AI admission, language registry, controls and review contracts—not its website content lifecycle. The smallest complete journey is **import evidence → choose an idea → edit script/caption/carousel → approve the exact package → plan a date → download for manual publishing**.

Read-only audit on 25 November 2026, repository `c5cc7c339d1a2b45bbd6574e2f951527729eab37`. Inspected source, migrations, existing tests, scan results and bounded database SELECTs. No source/dependency changes, database writes, provider calls, worker runs, mail, deployment or settings changes; only this plan is written. Tests/builds were not run. Source implementation is not production acceptance. These are proposed additions, not an expansion of accepted launch commitments.

## Smallest end-to-end MVP

1. **Sources and ideas:** read existing project knowledge without changing it; manually import a URL plus supplied excerpt, document or official report/export. Record provenance, title, source language, observation/import dates, locator, fingerprint, permission-to-use and explicit supplied metrics/window where present. A URL alone is not evidence; no automatic fetch/scraping. Separate factual support from creative inspiration. Ideas link to exact source revisions; unknown/stale/disputed claims remain flagged. Never invent trends, engagement, testimonials or outcomes.
2. **One content package:** manual drafting always works. With separately approved AI budget, one bounded request proposes up to three ideas; selecting one can request a script, caption/CTA and up to five slides together. Every factual claim references included evidence; machine ID validation plus human support review, not automatic truth certification.
3. **Editable branded carousel:** one 1080×1350 portrait template, 1–5 slides; editable text, order, approved colors/font/logo, supplied photos and alt text. Reuse raster validation and installed JSZip; browser-only Canvas rendering. Use rights-cleared assets and approved bundled fonts, no image-generation spend. Save editable JSON; freeze rendered PNG bytes for review/export. Missing branding/assets or text overflow blocks package approval rather than fabricating replacements.
4. **Approval queue and calendar:** owner authors/reviews first, matching the current owner-approval precedent. Delegates only when already authorized; viewer reads, editor edits, reviewer approves according to current project policy. Approval binds content, media bytes, brand/source revisions, language, channel, CTA and UTM manifest. Edits invalidate applicability; rejection retains history. Dates are planning only, stored with explicit timezone/UTC instant and DST validation.
5. **Manual export:** download approved PNGs, caption, script, alt text, editable JSON and evidence/UTM manifest in a ZIP. Draft-source downloads remain distinctly unapproved. Example parameters: `utm_source=instagram`, `utm_medium=organic_social`, stable campaign/item IDs—never personal data. Preserve valid existing URL parameters; reject unsupported destinations. Resolve Synergy’s relative booking CTA against its verified project origin. Record exported separately from owner-reported publication URL/time/channel. Neither event proves a live post or conversions.
6. **Honest measurement:** save campaign identity, expose the tracked links and accept genuine manual platform/GA4 report imports with their window and provenance. Missing metrics show unknown, not zero. UTM generation enables attribution; it does not establish that destination analytics captures it. Automatic social attribution/insights are deferred.

## Technical design and integration boundaries

- New `src/features/content-factory/`: schemas, pure evidence/version/UTM/calendar helpers, context adapter, repository, generation/review server helpers, authenticated `.functions.ts`, browser renderer and focused views/tests. Thin routes under `_authenticated/app.content-factory` for index, sources, editor, review and calendar; parent renders Outlet. Use existing AppShell/design tokens/controls and module translations; add only a gated navigation entry and appropriate leaf metadata.
- Extract `projectBrief` into a shared helper with parity tests and unchanged old callers. Read project/services through bounded scope-checked adapters; reuse `loadProjectKnowledgeContext`. Keep new manual imports in Factory storage so accepting social inspiration cannot change shared brand memory or weekly SEO generation.
- Proposed additive tables: `content_factory_projects` (trusted flags/limits, module brand kit), `content_factory_sources`, `content_factory_items`, immutable `content_factory_versions`, append-only `content_factory_events` (reviews, attempts, exports and reported publications). Use owner/project composite keys and project foreign keys; no new auth-schema references. Paginate lists (50/page); fail visibly at explicit pilot limits, never silently truncate. New private Factory storage isolates its files from article promotion/cleanup; reuse validation, not public-bucket lifecycle.
- Tenant scope is **owning account UUID + project ID**, not project name, host or browser active-project state. Derive actor from existing auth middleware. Every operation checks current membership, project existence, feature gate and required role; approval/export recheck authority, source and media versions transactionally. No whole-workspace fallback for a delegate, no cross-project caches, no caller-controlled owner/admin/budget grants. Use RLS and explicit least-privilege GRANTs on every new table; privileged flags/reviews/limits only through narrowly checked operations. Ordinary reads retain caller-scoped access. Private URLs expire; credentials never enter packages/logs.
- A trusted default-off `contentFactory` flag is pinned to the existing Synergy owner/project tuple; do not bind ownership to whoever signs in. Separate default-off capabilities for AI, local media, Meta publishing, analytics sync and autopilot. Server checks are mandatory even when navigation is hidden. Disablement stops new actions without modifying website publishing.
- **Forbidden coupling:** no writes to website `content`, `scheduled_publishes`, schedule mirrors, publication approvals, weekly readiness/executor state or existing team policies; no publication/preparation worker invocation; no edits to their gates, schedules or budgets. No existing GA4 daily-job changes. A Factory approval/date/export never triggers a connector.

## Language, privacy and cost limits

- MVP UI EN/PL/SV/DA using existing catalogs; all 24 EU content language codes accepted explicitly. Swedish pilot first, then English/Polish/Danish on request; other languages require fluent-review acceptance before claims of quality. Preserve source language and review each translated version separately; test diacritics, Greek/Cyrillic, wrapping and Stockholm DST.
- No patient records, identifiable treatment histories or unconsented photos. Sources are untrusted data, never instructions/tool authority. No terms-violating scraping or unsupported claims. Retention/deletion requires an explicit policy; no automatic deletion or new tracking without consent. Existing analytics consent is not publishing or autopilot authorization.
- **AI defaults to USD0 for Factory until explicit owner budget approval.** Proposal only: USD5/month pilot reservation sublimit, inside—not added to—the existing USD50 global ceiling. Current code reserves USD0.50/text attempt: that would allow at most ten attempts under this sublimit, not an estimate of actual invoices. Free accounts still need a manual grant. Atomically enforce module/account/global admission and stable attempt identities; uncertainty retains the reservation and prevents automatic regeneration.
- One provider attempt/action, no automatic retries/tools/benchmarks, max 64 KiB prompt and 8,000 output tokens, existing 60-second bound; strict complete-output validation. No new subscription, credentials, paid data, paid images or provider fallback. No provider availability or deployed budget setting was verified. Existing hosting/storage usage is not claimed free.
