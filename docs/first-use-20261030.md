Product scope, the USD50 monthly AI ceiling, manual free-account grants, billing, authentication, migrations and observers are unchanged; no dependency was added.

## Outcomes

1. **Compact first task.** The conversation home uses a new optional `AppShell` appearance (`appearance="conversation"`; default unchanged on every other route). Its header keeps the page title, the single project selector (`Client or project`, 224px wide from `sm`) and a native `<details>` **Manage** disclosure holding collaborator and conversation administration with the same destinations and search parameters on one row where they fit (sized so the Polish title fits beside them in the 723px content width at 1041px). On phones the selector and Manage share one row under the title; opening Manage puts its two links on their own line (inline, no overlay). The conversation's privacy indicator and, below the `xl` layout, the history toggle now share one compact row; the repeated project heading (`h2`) is screen-reader-only. The large welcome card with portrait and long description is replaced by `chat.welcome`, suggestions in two columns from `sm` up, and one short line of context (owned or shared) plus "a suggestion only fills in the message; nothing is sent", directly above the composer. The Refresh control is not rendered before anything exists to refresh (it was always disabled then). The composer starts at three rows. No fixed overlays.
2. **Permission disclosure.** Each per-message permission is a short checkbox label (`Allow one draft`, `Allow site checks`) with its bounded consequence always visible beneath it and wired as the checkbox description (`aria-describedby`): one draft for an existing topic, saved for review, content allowance, publishing separate; up to 2 site checks using the project owner's connected services and limits. The unchanged `chat.allowGeneration` / `chat.allowProviderChecks` wording sits in a keyboard-accessible native `<details>` per permission. When both permissions are offered they sit in two columns from `sm` up (one column on phones and for a single permission). The legend states that both are off by default and apply only to this message. `chat.usage` (AI allowance, content allowance, publication is separate) stays visible beside **Send**. Semantics are unchanged: unchecked defaults, generation control for the owner only, site checks for owner/editor/reviewer only (`firstUseConsent` mirrors the send contract and is used for rendering only), state reset after a saved send and on any scope/role change (the session key is untouched), the exact `submit()` flags, busy/uncertain handling, recovery, escape handling and separate publication. Suggestions never consent.
3. **Truthful context suggestions.** `src/lib/milo-first-use.ts` (`firstUseContext`) decides the suggestions from data already in memory; no fetch, generation, count or ranking. A draft is named only when the actor is the selected project's owner **and** the store is hydrated **and** `store.userId` equals the actor, and only from `store.content` entries of that exact project in status `Draft` or `In Review` (latest `updatedAt`, store order on ties or unreadable dates). Titles are stripped of control/zero-width/bidirectional characters, whitespace-collapsed and limited to 60 code points with an ellipsis. Shared projects (any owner other than the actor, including an identical project ID) always get neutral suggestions; unhydrated, stale or other-account workspaces stay generic. An empty owned project gets "What is missing from my saved business information?" and "Help me choose one clear goal and a first step." The route derives suggestions and passes them down; the welcome only renders inside the existing concealed/authorization boundary of `ConversationSession`. A suggestion only fills the composer and moves focus.
4. **Warm premium consistency.** A scoped `.milo-app.milo-conversation-skin` block in `src/styles.css` sets warm ivory background, graphite text and primary actions, restrained gold as decoration (header hairline, focus-within border, link underline, chip hover), Fraunces 500 for the page title and welcome heading (already loaded through `@fontsource/fraunces`) and Inter for body text, rounded suggestion chips, a softly shadowed composer and 44px controls for the selector, Manage, suggestions and Send. Contrast on the ivory background (computed with the WCAG formula): text 13.9:1, muted text 6.3:1, focus outline 5.7:1, field borders 3.1:1; gold (2.7:1) is never used for text. The dark sidebar, its navigation and focus colours, and all other screens are unchanged. No new assets, animation or dependencies.

## Internationalisation

New namespace `conversationStart.*` (17 keys) in `src/i18n/first-use.ts`, with authored English, Polish, Swedish and Danish text, registered last in the central catalog `OVERRIDES` and read through the central `useT`. No `chat.*` key or byte changed, so the conversation source fingerprint and the twenty staged `conversation` batches are unchanged.

Registering a new runtime namespace makes every staged catalog miss those keys. The independently confirmed and explicitly authorized dependency expansion was applied, following the billing fallback pattern:

- `src/i18n/staged/first-use-fallback.ts` and its focused test: exactly the 17 `conversationStart` keys resolve to their reviewed English source as declared fallback pending translation and interface acceptance. Not a translation, review or readiness claim; no other namespace is covered.
- One `first use` batch appended to each of the twenty aggregators (`bg cs de el es et fi fr ga hr hu it lt lv mt nl pt ro sk sl`), with the recomputed source fingerprint `5368dd8f…29b2` (after the copy shortening below); German records it only in `de-source.ts`.
- The fixed staged total changed from 4693 to exactly 4710 (= 4693 + 17) in the fifteen locale tests that pin it and in `billing-screen-fallback.test.ts`. The five unchanged-English tests (Irish, Maltese, Lithuanian, Latvian, Romanian) gained a separate exact-key `conversationStart` partition (asserted equal to the source keys, size 17, values equal to English) beside the existing 126-key billing partition. All other equality, uniqueness, frozen, existing-value, 180/54/126, source-hash and activation assertions are untouched. No staged locale was activated.

Visual correction (same day, after Codex's browser preflight): the shorter wording of nine keys per locale (contexts, hint, four suggestions, two permission summaries) keeps every consequence: one draft, existing topic, saved for review, content allowance, publishing separate; up to 2 checks, project website, owner's connected services and limits. The key set, count (17) and placeholders are unchanged; only the pinned fingerprint moved.

## Browser fixture

`scripts/milo-conversation-browser` gained a `firstuse` mode (see its README): the actual home route, shell, picker and workspace through a real memory router with the real stylesheet; synthetic auth/store/membership/conversation mocks; an inlined network guard; `?locale=en|pl|sv|da`, `?variant=empty|draft|viewer|editor`, and `?check=1` for a scripted five-group report with layout and font metrics. Output defaults to `/tmp/milo-first-use-browser-20261030`; `MILO_BROWSER_OUT` / `MILO_BROWSER_STYLES` override output and stylesheet for any mode. The `full`, `generation` and `firstuse` modes now redirect the shell's relative `./store` import to the synthetic store, which also gained the save-status exports the current shell reads (the `full` build previously pulled the real store, Supabase client and server-only modules and failed to bundle). Two existing assertions (`component`, `full`) now read the short site-check label and find the unchanged full wording in its details.
