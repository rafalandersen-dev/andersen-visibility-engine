# Knowledge used by saved output

Milo records the exact reviewed knowledge versions used in generated articles and images. Publication now rechecks those versions against the current private project knowledge. It holds output when a record or its source is withdrawn, forgotten, replaced, expired, disputed, conflicting, or no longer applicable to that output medium. Explicit owner brand overrides use the same filtering rules as generation. Current values are never silently substituted into an old article or image.

The shared check runs before manual WordPress, Shopify and custom draft/live transports and scheduled publication, alongside existing exact-version approval and website-source checks. Project Setup's affected-draft list also shows knowledge issues, including expiry at a saved future publication time. This view reads saved evidence; it does not fetch a provider or website. Existing article text, owner edits, image approval and publication approval are preserved. A previous approval does not bypass a knowledge hold.

References are retained in the existing private output-dependency registry in the same transaction as the immutable generation result. Browser omission and archive discard cannot erase references for saved output. Discarding a result that was never attached releases its registry row. Its existing archive tombstone retains only the project/asset/output identity and, for an image, its storage path; late attachment of that discarded output is refused. Existing reused copies retain their own references. Project deletion clears the minimal discarded identity. Reusing an approved image copies its registry evidence by its saved same-owner/project public URL, in the existing atomic workspace update. Moving an image within an edit preserves that evidence. Removing an image removes that image's use from the draft. Forgetting a knowledge record or source removes the corresponding identifiers from registry references and preserves only an unavailable-evidence marker. Project/output deletion uses existing cleanup.

A hold is conservative: editing the article does not certify that the old knowledge is no longer used, and accepting a new knowledge revision does not retrospectively review old output. A temporary read outage clears when the original evidence can again be confirmed. For withdrawn or replaced evidence, remove an affected image when appropriate, or prepare a new draft/output using current reviewed knowledge and review it before publication. When the original records have current accepted, applicable replacements, the owner can now use [explicit saved-output revalidation](OUTPUT-KNOWLEDGE-REVALIDATION.md) to inspect the deliverable and each fact. The review binds exact content and current evidence, and cannot waive forgotten or unavailable facts. No automatic paid regeneration or new approval occurs. The existing history controls remain available for investigating the source change.

The registry remains bounded at 1,000 output records per project. Each output has at most 300 knowledge references. The read endpoint accepts at most 100 asset IDs; Project Setup reports the uninspected remainder. Existing legacy output with no recorded knowledge cannot be retrospectively verified. The migration explicitly refuses an installation with previously retained nonempty knowledge archives until a separate backfill is reviewed; the current release requires verifying the zero-archive baseline.

This closes a specific publication-integrity gap; it does not establish factual correctness, product-image fidelity, live destination retention, or signed-in acceptance. Product-reference image generation remains open: the current image generator uses text only. The official GPT Image 2 guide confirms edits with reference inputs but the linked vision-cost rules explicitly exclude GPT Image generation/editing. No supported input-token ceiling was established for the required reservation guarantee, so this change neither adds an edits transport nor assumes that the existing USD0.10 prompt-only reserve funds references. See [image generation](https://developers.openai.com/api/docs/guides/image-generation) and [GPT Image input pricing scope](https://developers.openai.com/api/docs/guides/images-vision#calculating-costs), checked 10 September 2026. No model migration, provider call, funding or key setup is part of this change.
