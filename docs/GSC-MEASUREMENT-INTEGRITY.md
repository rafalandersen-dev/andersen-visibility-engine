# Search Console measurements and CSV intake

Analytics keeps the existing Google OAuth connection and sync controls. Manual CSV now has a local preview followed by a separate save action. Select one standard Query, Page or Date table, declare its Search Console property and inclusive start/end dates, and review the first five rows before saving. Up to 1,000 rows, 16 columns, 4,000 characters per cell and 2 MB are accepted. Oversized files are rejected, not silently truncated. Five manual imports can be retained; explicitly remove one before adding another. Existing automatic sync retains its established rolling five-import policy.

Each CSV has one dimension. Duplicate headers, unsupported columns, uneven rows, broken quotes, repeated dimension identities, invalid counts, negative/nonfinite numbers, clicks exceeding impressions and invalid/out-of-window dates fail validation. Counts are integers without thousands separators. Decimals use a dot or comma; CTR is a 0–1 fraction or an explicit percentage. Blank or absent metrics remain unavailable (`null`); explicit zero stays zero. Invalid numeric text is never stripped into a plausible number. Position zero is not a rank. CTR/weighted position with no positive impression denominator remain unavailable.

Page imports require full HTTP(S) public URLs within the declared domain or URL-prefix property. URLs containing credentials, query strings or fragments are refused rather than silently simplified; export a suitable public-page table when these occur. Domain matching requires exact hostname or a proper subdomain boundary. Page attribution requires full URL identity, preserving protocol, www, hostname, path case and trailing slash; no alias/canonical URL inference is made. Duplicate page rows and combined query/page/date rows cannot be added into a page observation. Onsite path-only statistics have a separate window and are now referred to separately.

A CSV summary is a subtotal of that table, not total property traffic. Different dimension tables may overlap, and query anonymization, filters and omitted rows limit coverage. API sync retains its separate no-dimension property aggregate, query sample and page sample. No aggregate response means unknown totals, never a fallback sum of both samples. API metrics retain precision and missing values. Successful malformed JSON, invalid shapes/metrics/keys, unexpected row counts, duplicate keys and unsafe/out-of-property page URLs fail the sync instead of saving false empty data. Each analytics request has a 20-second timeout and a 2 MB response limit. No pagination or completeness beyond Google's top-row response is claimed.

API windows now contain exactly 28 or 90 inclusive Pacific calendar days, with the existing three-day lag. Requests explicitly use web search and finalized data. Google documents inclusive Pacific endpoints and top-row limitations in the [Search Analytics query reference](https://developers.google.com/webmaster-tools/v1/searchanalytics/query).

Analytics, monthly proof UI/email and MCP summaries recompute measurements from the new structured format and show the basis, declared property and separate window. The observation is not necessarily for the report month or since publication. Search clicks do not establish conversions or causality. Source labels, the format version and selected property live in browser-writable workspace data; they are **not independent provider verification**. Launch connection cards also treat imports as partial evidence, not proof that OAuth is currently connected.

Legacy records remain unchanged. Their former parser may have synthesized zeros or mixed overlapping tables, so their numeric basis is shown as unavailable instead of retroactively claiming validation. A fresh export/preview or explicit API sync can create new evidence. New publication observations require the new format, exact page/property, complete metrics and the existing fixed-window checks. Already frozen historical publication evidence is not rewritten; its existing unverified provenance remains intact.

The release uses mocked provider responses, pure regressions and static component rendering. It does not reconnect Google, run a live sync, import production evidence, change OAuth credentials, send email, change timers or migrate the database. Signed-in/browser and real provider acceptance remain separate and unverified.
