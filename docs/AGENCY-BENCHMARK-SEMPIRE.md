## 5. Claims Milo rejects — and the defensible reason (corrected wording)

**General position (use verbatim):** *There is no reliable evidence or documented search‑engine support showing that arbitrary `data-*` attributes, HTML comments, custom AI tags, or CSS class names improve ranking, AI citations, or AI visibility. The supported approach is standard schema.org structured data, visible content, crawlability, source authority, and factual consistency.*

| Sempire claim (AI 3.0 unless noted) | Milo position |
|---|---|
| **`data-*` attributes "to pass AI specific information"** | Not a supported content signal — `data-*` exists for a site's own JavaScript. No documented search/LLM support that they influence ranking, citation, or AI visibility. **Reject.** |
| **Custom semantic tags / custom microdata "for AI"** | Only recognised vocabularies (schema.org) are consumed. No evidence custom tags/attributes are read as AI signals. **Reject; use standard schema.org instead.** |
| **HTML comments "to give AI additional context"** | HTML comments are not rendered content; no documented evidence they are used as a ranking/AI‑context signal. **Reject.** |
| **`<div class="ai-summary">` as an AI signal** | A visible TL;DR/summary genuinely helps readers and is good practice — but the **class name itself carries no documented AI meaning**. Milo ships the *visible summary* (Article Studio TL;DR), not the myth that the class name does anything. |
| **"Unlimited keywords" (nielimitowane)** | Vanity metric unconnected to revenue. Milo sells governed, evidence‑seeded opportunities, not phrase counts. **Reject.** |
| **Content as characters/year (34k–100k)** | Raw‑volume quota unconnected to intent/revenue. Milo caps by quality + `PUBLISHING-CAP.md`, not a character quota. **Reject the metric; win on real capacity.** |
| **Knowledge‑Graph "optimisation"** as a deliverable | KG presence is emergent; you can't guarantee an entry. Milo builds the *inputs* (Organization/author schema, `sameAs`, NAP consistency) and never promises the KG entry. |
| **"AI mention + sentiment monitoring", "AI Overview reporting", "LLM referral reporting"** with unspecified method | Legitimate *concepts*, but non‑deterministic and often near‑zero/noisy; must be shown with **confidence + stored evidence**. Milo builds these **honestly** (three separate metrics, evidence‑linked — `AI-VISIBILITY-MONITOR.md`), and rejects any dashboard that renders noise as data. |
| **Voice‑search optimisation** as a line item | Low‑ROI; covered by FAQ/conversational content. No dedicated module. |
| **"AI 1.0/2.0/3.0" packaging** | Arbitrary version branding of a bundle. Cosmetic. |
| **"SEO Guarantee"** | Actually only a renegotiation right. Milo keeps **no ranking/traffic guarantees** and says so plainly. |

**Rich‑result honesty (applies to Milo's own schema work):** Milo distinguishes **structured‑data implementation** (we do this) → **rich‑result eligibility** (we can indicate this) → **actual rich‑result appearance** (Google decides — never promised).
