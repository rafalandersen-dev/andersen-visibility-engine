Each row states the strongest evidence that exists, and its date. Five evidence classes are used, and they are not interchangeable:

- **Documented route** — the vendor's own page describes a way to add a custom MCP server. Says nothing about Milo.
- **Static implementation** — Milo's source at main `f639ecae` implements the server side. Not a client test.
- **Dated live smoke (July 2026)** — an owner-only window recorded in this repository. Historical; it is not evidence of today's production state.
- **Current live production evidence** — an observation recorded on or after 27 September 2026 against the deployed build.
- **Untested** — no Milo-specific observation of any kind.

Every OAuth-route row above additionally presumes a deployment with `MCP_OAUTH_ENABLED=true`; when the flag is off or unset those endpoints return 404 by design, and the production flag state is unverified in this review. Direct probes of Milo's OAuth metadata endpoints from the review environment were not possible (environment restriction); that is not evidence of an application failure and no row relies on it.

## What would change a row

- Missing test evidence is not evidence of absence: historical grants exist, and a client may be in use without a recorded observation. A current live production observation for the Claude.ai read connector needs one connector call from a Claude account against the deployed build, recorded with date and build identity. It is a real account action and is not performed by documentation work.
- Any "Untested client" row needs a real connection from that client, which requires an eligible account on that vendor's terms (admin rights, region, plan) and the owner's decision; nothing here authorises it.
- The write/propose rows need the operator to switch the deployment flag on for a bounded window, as in July 2026; that is a deployment change, not a UI setting.
