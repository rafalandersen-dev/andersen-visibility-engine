# Local and international coverage

The On-page Review screen now includes a coverage workflow independent of its paid homepage audit. It reads existing private project knowledge and publication receipts; opening the panel does not scan a site or connect a provider. Saved project locations and the primary market/content-language pair offer entry points for missing records. A reviewed-record badge means a record exists, not that the target has complete coverage.

Owners can record a location/service or market/language, public business name/address or service area/phone, destination page, directory/citation, review and Google Business Profile evidence URLs, corresponding alternate-language URL, source locator/observation date and notes/next action. Blank fields remain missing evidence. HTTPS evidence URLs reject credentials, queries and fragments; each complete structured entry is bounded by the existing 2,000-character knowledge value limit. No URLs are fetched by this workflow.

These are structured `coverage.local.*` / `coverage.global.*` fact records in the existing project knowledge store, not a duplicate store or browser workspace authority. An explicit owner statement is saved as owner-reviewed knowledge. A claim attached to a current saved source starts proposed; a separate review accepts that version. Existing authenticated owner/project scope, source/record revisions, expiry, revocation, compare-and-swap updates, history, dispute/reject/forget and source dependency controls continue to apply. The source/history link opens the existing knowledge controls. On an uncertain mutation result, the form holds until a successful refresh; refresh clears the ambiguous draft so retained records can be inspected before another mutation.

Only currently eligible records are labelled reviewed. Malformed records remain visible for repair but cannot enter generation. Conflicting nonempty NAP values for the same normalized local target, or differing evidence URLs for the same target/service/language, withhold all involved records from both the panel's reviewed set and the shared generation knowledge selection. Different service URLs are not an NAP conflict. This is a conservative comparison of saved claims, not an audit of external NAP consistency. Labels should identify distinct locations when multiple offices share a city.

The panel displays paginated actual publication receipts with exact page-URL matches to current reviewed coverage. Matching is deliberately exact: redirects, trailing slashes and alternate URLs are not inferred. A receipt match retains the published title, timestamp, outcome and version hash; Reports exposes the immutable snapshot and saved measurement observations. A match does not prove that the published content covers the claimed service, location or language. Missing matches on one receipt page do not prove no publication exists elsewhere. Each page contains up to 50 receipts, with the existing 1,000-record read bound.

The Plan link opens the existing manual content-planning workflow; no opportunity, content generation or publication is triggered on the owner's behalf. The Setup link edits project targets. All new panel copy is supplied in English, Polish, Swedish and Danish. This does not claim a 24-language interface.

Google Business Profile connection/listing control, live listings, review authenticity, actual page presence, hreflang implementation, Google acceptance, local rankings, international performance, deeper vertical playbooks and signed-in acceptance remain unverified/open R17 work. R18 live CMS/product-reference acceptance and R20 wider localization remain separate. No new migration, schedule, provider fetch, generation, funding, email, outreach or client publication is part of this release.
